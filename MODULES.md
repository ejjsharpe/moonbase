# Moonbase module boundaries

The architecture requirements in `AGENTS.md` apply to every module. Keep Nx/Bun `apps/*` and `packages/*`, Electron, React, TypeScript, Monaco, StyleX, Base UI and Effect 4.1.0. Feature ownership separates work, not application runtimes.

| Owner | Public boundary | Allowed dependencies |
| --- | --- | --- |
| Coordinator: `packages/application/**` | `./client`, `./host-client`, `./connection-client` browser-safe boundaries; `./services` Effect contracts; `./handlers` shared dispatch; `./runtime-client` process adapters; privileged `./host-health` | Effect; no feature implementation imports |
| 02: `packages/editor/**` | React editor, per-instance state/controller and in-memory demo adapter | application/client, shared UI, React, Monaco; demo adapter may implement application/services outside renderer |
| 03: `packages/workspace/**` | `WorkspaceLive` layer/configuration, focused native assets | application/services and client types, Effect, Node/platform/Git/native resources; no React/Electron/provider dependency |
| 05: `packages/pi-runtime/**` | chat service/layer and validated loopback protocol implementation | application contracts, Effect, pinned Pi Durable/Pi dependencies, Node/SQLite; no editor/Electron/React |
| 06: `packages/ssh/**` | `SshLive(config)` provides shared ConnectionService | application contracts, Effect, system OpenSSH; no editor/Pi implementation |
| Coordinator: `packages/ui/**` | StyleX tokens/recipes | StyleX; Base UI interactions belong in consuming React controls |
| 04/08: `apps/desktop/**` | Electron main/preload and renderer composition | public module exports; one scoped process runtime; privileged implementations stay out of renderer |
| 07: `apps/chat-probe/**` | independent chat proof | public application/chat/SSH interfaces and UI; no editor |

The coordinator owns root configuration, package export maps, lockfile, CI and shared UI. Feature workers may create their own package manifest/test/build configuration inside assigned paths, using pinned installed versions, and request coordinator installation/lockfile changes. No cross-module internal imports. Tests may construct scoped runtimes; feature production code must not.

## Frozen editor interface

`packages/application/src/client.ts` is the source of truth for shapes. `EditorClient.command` enters `workspaceCommand`; all UI/keyboard/native/IPC paths use that function. `WorkspaceService` maps explicit named operations to Effects; its `watch` is a scoped stream. `makeEditorClient` receives the process root's runtime instead of constructing a second one. Use one memoized `WorkspaceLive` layer in that root. No global serial command queue; serialize only conflicting file/recovery resources. Each editor instance owns buffers, view state, selection, close history and client identity.

`CheckoutTarget` binds host, checkout, project, root and branch. A root string from a renderer is not an approval: only `openCheckout` after a native/user-authorized selection grants a root, and every operation revalidates exact identity and path. Transports must authorize each caller/client and validate unknown inputs before calling handlers. Internal in-memory adapters are trusted, not production persistence qualification. `openCheckout` is not exposed to arbitrary unauthenticated network callers. Directory paths may be empty for root; file paths are nonempty relative names, with no traversal, `.git`, NUL or symbolic-link traversal. Check 2 MiB and UTF-8/binary limits for editable data; native copying retains separate limits.

`readFile` returns text and a content version; `saveFile` uses the captured `expectedVersion`. Conflict returns the latest disk document while the client retains its dirty text and original baseline. Overwrite is a deliberate second save against the newly observed version, never a force flag. Preserve practical check-before-replacement guarantees and honestly document the external-writer race. `clientId` and immutable `requestId` bind a save; retries must never silently substitute a different payload or target. Failed/uncertain persistence must remain observable even after a filesystem change.

Recovery publications also bind an immutable `requestId`, expected revision and full snapshot. `persistRecovery` returns the original exact receipt on matching retries before CAS; changed reuse rejects. `getRecoveryPublication` resolves only that identity. Never infer ownership from a loaded latest revision or equal state. Keep captured drafts through fallible close preflight, then treat the exact final destructive receipt as the close commit; unresolved delivery retains live buffers and pending evidence. See `packages/application/RECOVERY-PUBLICATIONS.md`. Both adapters must adopt this boundary together.

`inspectEntries` captures exact source identities for `mutate`; the service revalidates them before changing files. `WorkspaceOperation.id` binds immutable payload/client/checkout, and `operationStatus` resolves a lost response without redispatch. Replacements require captured destination identities and explicit UI consent. The client preserves affected dirty drafts before a mutation. Results report per-item completed/failed/uncertain outcomes; reconcile only known successes. Journal before effects; restart never repeats an uncertain mutation automatically. Operation acknowledgement occurs only after client recovery publication succeeds. Native imports use opaque, scoped single-use references issued by the privileged workspace/native adapter after a native picker/drop; raw renderer filesystem paths grant no import authority.

Every `OperationResult`, including persisted/recovered evidence and failed or uncertain results, carries its original immutable `checkout`. Reconcile only matching host/checkout/project/root identities; identical relative paths in another checkout grant no authority. Missing or incompatible evidence stays visible and retained, never guessed from a path or automatically replayed.

Operation evidence binds origin `clientId` plus `id`; acknowledgements bind the observing `clientId` and original `operationClientId` separately. Retain a fact for each affected client until that client publishes its reconciled recovery and acknowledges it; the origin's acknowledgement must not hide foreign move/copy evidence from another live client. `loadRecovery` returns the immutable exact-checkout results still relevant to that observer.

Saved results and operation evidence carry `recoveryChanges` with exact `{clientId, previousRevision, revision}` transitions caused by publishing their known facts. Empty means no recovery revision changed. Clients apply only a contiguous known transition from their current revision and preserve current local text/views while reconciling exact references. A gap or unrelated CAS conflict remains visible and vetoes publication/close; never blindly adopt the latest loaded revision. Status/retry returns the retained transitions instead of inventing a new write. A Save updates only its originating client's baseline; another dirty client's original baseline and conflict protection remain intact. Known moves may remap other clients' paths while retaining their text and baselines.

Recovery has an explicit client namespace and compare-and-swap revision. One client's publication never overwrites another's drafts. Validate full state, size and exact identities. `loadRecovery` retains unavailable checkout references and reports errors/operation evidence. Persistence failure vetoes removal/discard. Captured Save/Discard/Cancel batches defer all proposed discards until every choice and publication succeeds; successful earlier saves remain facts. Window hiding retains models; explicit Quit uses the same preservation gate.

Recovery `checkouts` is the retained registry of known exact targets, including closed checkouts. `openCheckoutIds` is unique open membership and a subset of that registry; `selectedCheckoutId` is null or an open member. `views` keys are exactly `CheckoutTarget.checkoutId`. Views and recents may reference known closed targets so closing/reopening retains file order, active/comparison selection, positions and tree memory. Closing removes open membership after preservation; it does not delete that metadata or create a Reopen Closed file action. UI tabs, lookup scope, watch installation and initial discovery use only open membership. Initial restoration probes open targets; it need not access closed directories. Known operation facts may reconcile saved metadata for closed targets without opening them or granting new filesystem authority. Validate all reconciled snapshots before committing; capacity failures retain previous valid recovery and pending evidence instead of truncating drafts.

Watch streams bound/coalesce notifications and release resources when views end. Unsubscribing never changes file buffers. Git staged comparisons show HEAD against the shared editable working buffer; unstaged compares index against that buffer. Lookup must be independently implemented: the old Microsoft scorer is excluded. Report partial discovery and unavailable Git/ignore policy rather than inventing complete results.

Acquire watch resources in the enclosing stream scope: `Stream.unwrap(Effect.as(Effect.acquireRelease(acquire, release), events))`. With pinned Effect 4.1.0, placing asynchronous acquisition/finalizers inside `Stream.callback` can lose cleanup defects when unsubscribe races acquisition. A callback may publish bounded events, but its resource acquisition/release belongs to the outer scope. Public-client tests must cover unsubscribe during acquisition, including concurrent process-runtime disposal, and observable cleanup failure. Commands reject already-aborted signals before service dispatch; in-flight cancellation remains cooperative and cannot undo admitted filesystem effects.

Wrap external resource finalizers with `releaseResource(() => resource.close())` from `application/services`. It normalizes arbitrary thrown/rejected values before Effect combines causes: a throwing proxy in an unnormalized cleanup defect can make pinned Effect discard the original service failure. Pure local finalizers that cannot fail need only ordinary `Effect.sync`. Keep typed uncertainty and exact target observable alongside cleanup detail.

Lookup returns ranked `LookupMatch` values with positions for highlights. Apply the independently implemented same matching rule to supplied checkout-scoped history and enumeration: case-insensitive ordered characters, case/consecutive/boundary/basename/path relevance, all whitespace-separated pieces, quoted contiguous pieces. Blank input shows history. Typed history remains a separate deduplicated group with its deliberate exclusion exception. Exact entered paths retain their in-scope no-follow exception; no result approves an outside path. Keep existing local/nested ignore semantics, default exclusions and explicit partial/capped discovery. Disclose tool failure; unsupported normal policy is a technical gap, not completed acceptance.

## Editor acceptance and source use

Retain checkout/file tabs; shared normal/diff/conflict buffers; explicit Save; conflict compare/overwrite/reload/cancel; preview/Keep Open; order/MRU/visual navigation/reopen; tree/lookup/reveal/ignore filtering; view positions; safe captured close and restart recovery; create/rename/move/Trash/copy/import with collision and dirty-work preservation. The source specs and safety fixtures in `docs/source-snapshot` record detailed behavior. They are reference-only and not a runnable app or authorization to import excluded dependencies. Use only verified user-authored portions. Excluded dependency behavior is reimplemented independently. Record any additional source reuse with original hash/history/decision.

## Host identity contract for later chat/SSH

Host health uses the nonce-bound HMAC protocol in `packages/application/HOST-PROTOCOL.md`, with no reusable key disclosure or bearer fallback. `CONNECTION.md` defines the independently reviewed scoped SSH interface. `CHAT.md` defines exact personal actor/host/store/conversation/request identities, two-phase Pi-owned admission, bounded history/progress and exact-task Stop. Health alone does not authorize stateful requests. The shared typed clients enter the same application handlers; real transports validate/authenticate unknown inputs and enforce the stateful protocol before dispatch. No editor startup dependency, remote provisioning, automatic resend or remote-to-local path mapping.

## Technical gates and branches

Foundation → independent editor/workspace siblings → reviewed editor fan-in → standalone editor proof. Then stable contracts → independent Pi/SSH siblings → reviewed chat fan-in → standalone chat proof. Prepare composition only when independent interfaces and available checks are sound; keep final composition draft while real/manual gates remain. Non-default fan-in branches preserve ancestry; original PRs stay unmerged. Track exact refs, review rounds, checks and blockers in `docs/overnight/ledger.md`.
