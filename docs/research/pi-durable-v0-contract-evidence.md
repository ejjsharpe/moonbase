## 1. Storage, lifetime, restart

**Evidence:** `openNodeSqliteStorage(path: string, options?: NodeSqliteStorageOptions): Promise<SqliteStorage>`; options are `{ prefix?, busyTimeoutMs?, walAutoCheckpointPages? }`. Sequence: open storage → `Harness.open(storage, { models, registry: createRegistry(), ... }, context)` → open/create conversation → `harness.resume()` for unattended recovery → `await harness.close(context)`. Close owns storage closure, signals/joins invocations without terminalizing tasks; interrupted work resumes after reopen. Read-only access does not enable scheduling; submit/wait does. Restart limit defaults to five, then tasks park. Use `inspect`, `closed`, `onReport` for observable failure. A failed storage call generally fails/closes the Session. [Node API](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/storage/sqlite/node.d.ts), [Harness API](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/types.d.ts), [lifecycle/recovery](https://unpkg.com/@earendil-works/pi-durable@1.4.0/README.md).

**Evidence:** one process must own storage; Durable provides no cross-process ownership lock. Chord uses synchronous `node:sqlite`, WAL/NORMAL, `BEGIN IMMEDIATE`; default busy timeout 5000 ms. Small timeout is exposed. For exclusive policy the public route is `openNodeSqliteDatabase(path, options)` → `db.exec("PRAGMA locking_mode=EXCLUSIVE")` → `SqliteStorage.open(db)`; no typed exclusive option. SQLite acquires/retains locks on access, not merely setting the pragma. **Inference:** usable primitives, not an already-qualified ownership guarantee; require successful lock acquisition before serving. Timeout bounds synchronous contention, not ownership. WAL/NORMAL can lose recent commits on power failure. [Chord facade](https://unpkg.com/@earendil-works/chord@1.4.0/dist/sqlite/node.js), [SQLite rules](https://www.sqlite.org/pragma.html#pragma_locking_mode).

**Evidence/inference:** text-only Harness needs Node SQLite and ordinary dependency files, no QuickJS/photon worker/WASM initialization: root imports do not select codemode/images. Retain selected providers' `dist/providers/data/*.json` catalogs; faux needs none. `env` is optional; filesystem/shell tools need an injected environment, e.g. `NodeExecutionEnv({ cwd })`. This is source evidence, not packaged asset qualification. [Exports](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/index.js), [catalog import](https://unpkg.com/@earendil-works/pi-ai@1.4.0/dist/providers/openai.models.js), [Node environment](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/env/node.d.ts).

## 2. Admission and immutable receipts: published blocker

**Evidence:** 1.4.0 exposes only `conversation.submit(draft: SubmissionDraft, context: Context): Promise<Submission>`. Draft is `type: "input"` with `content`, optional `requestId`, `whenBusy: "steer" | "followUp" | "reject"`, optional display entry; or `type: "write"` with entry. Deduplication looks up `(conversationId, requestId)`, checks only matching submission **type**, and returns the original ID regardless of changed content/queue policy. It binds neither authenticated actor nor host/store. [Published signatures](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/types.d.ts), [admission implementation](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/submissions.js).

**Inference:** required immutable actor/store/target/request/payload binding plus admission in ONE Pi transaction is unavailable through this published public admission API. `defineDoc`/`defineDocFamily`, `commit`, `tx.doc` exist, but a separate receipt commit leaves a crash gap. `tx.createSubmission` explicitly skips admission rules; internal `admitSubmission` is not package-exported. Do not substitute either. [Transaction API](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/types.d.ts), [exports](https://unpkg.com/@earendil-works/pi-durable@1.4.0/package.json).

**Main-only evidence:** sampled main `2c8d1feb147f6b3d97e855da803bfe7b19f3c403` exposes `submit(tx: Tx, draft: SubmissionDraft): Promise<SubmissionId>`. Necessary sequence: `commit` → `tx.doc` check actor/host/store/conversation/requestId/canonical-payload receipt (return matching receipt; reject mismatch) → `submit(tx,draft)` for new request → record receipt with returned ID → await commit → `harness.submission(id,context)`. App enforces immutable equality. Admission precedes any table write; documents may change on either side; foreign transactions reject. This is **not 1.4.0**. [Exact main declaration](https://github.com/earendil-works/pi/blob/2c8d1feb147f6b3d97e855da803bfe7b19f3c403/packages/durable/src/harness/types.ts#L812-L822).

## 3. Stop identity

**Evidence:** `harness.abortTask(id,context): Promise<"marked"|"terminal">` marks/signals/joins the invocation, then schedules abort handling; completion requires `waitForTask(id,context)`. Verify `getTask(id,context).conversationId` before aborting; unknown task rejects. `abortSubmission(id,context,conversationId?)` returns `"aborted"|"already_placed"|"settled"|"not_found"`: it withdraws queued input, never stops placed work. `conversation.abort(context,options?)` withdraws queued inputs and aborts current ordinary work, waiting for idle; it is not generation-specific. [APIs](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/types.d.ts).

**Evidence:** read `(await harness.snapshot(LiveDoc,conversationId,context))?.run`, containing `{ taskId, inputs: SubmissionId[] }`; views expose the same document. Task ID survives the request/tool wait but **changes after tool rounds and onYield continuation** through successor generation creation. [Live declaration](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/live.d.ts), [handover](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/generation.js). **Inference:** bind Stop to verified host/store/conversation plus captured task ID; never replace it with the latest ID. A delayed Stop may miss a successor of the same input, but cannot cancel a later task. No stable whole-run generation token or public transactional compare-and-abort is exposed.

## 4. Saved chats, history, observation

**Evidence:** list via `harness.commit(tx => tx.scanConversations(query,limit,cursor),context)`; create via `createConversation({ ownership: { kind: "ownerless" }, agent?, init? },context)`; open via `conversation(id,context): Promise<Conversation|undefined>`. `init(tx,id)` can write app metadata atomically; records contain identity/ancestry/ownership, not title/timestamps. Model/cwd live in agent configuration. `entries(query,limit,cursor,context)` returns `{items,next?}`, descending by default. [Declarations](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/types.d.ts), [conversation API](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/types.d.ts).

**Evidence:** `watch(context)` → read `.value` → `.start((value,ops)=>...)` → `await .stop()`; `viewState(context)` instead requires `.dispose()`. Reattach reads current state, never resends/aborts work. Pending watches coalesce after 100 frames, but each view contains the **entire active transcript**; no window parameter/byte bound. Paginated history is bounded by entry count, not entry bytes. Progress is throttled (default 100 ms) and published after storage; 1.4.0 has **no deferred-persistence option**. `generation.deferred` denotes provider polling. Admission is persisted separately from `Submission.status/wait` completion (`done`/`unanswered`). [Published view](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/view.d.ts), [observation/progress](https://unpkg.com/@earendil-works/pi-durable@1.4.0/README.md).

## 6. Follow-up: public 1.4.0 alternatives

**Inference:** 1.4.0 remains a candidate. The earlier blocker concerns a single-transaction claim; the actual brief can instead retain explicit intermediate states, using Pi documents without another scheduler/store.

**1 — Evidence:** `defineDoc`/`defineDocFamily`, `Harness.commit(change,context)` and `tx.doc` support an atomic reservation of immutable actor/store/conversation/request/payload, before ordinary `conversation.submit`; a later commit binds its submission ID. **Inference:** reserve by conversation+requestId, enforce equality on every admission path, retain reservations, and never overwrite mismatches. This is two-phase, not atomic reservation+admission. [Published document API](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/documents.d.ts).

**Evidence:** public `Tx.submissionByRequest(conversationId,requestId): Promise<SubmissionRecord|undefined>` enables `harness.commit(tx => tx.submissionByRequest(c,r),context)` without submitting. Records include `id`, `conversationId`, `requestId?`, `type`, `status`, and lifecycle-dependent `entry`/`answer`/`reason`. Lookup first, then `tx.doc` can bind an existing record in that commit; `harness.submission(id,context)` reacquires its handle afterward. **Inference:** a found admission resolves the crash gap without Send. Undefined means no committed admission at that read; retain the reservation. In-flight admission or failed lookup stays pending/uncertain; only explicit same-ID, same-payload retry may submit. Reconnect/startup never submits automatically. [Public Tx/record declarations](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/types.d.ts), [lookup implementation](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/session/transaction.js).

**2 — Evidence:** `harness.subscribeCommits((publication,context)=>...):()=>void` observes committed entry/task/submission/document changes; filter their conversation identities. Its synchronous callback must not block/call Session APIs. `subscribeClose(listener):()=>void` reports closure. `HarnessOptions.onReport(error,info)` covers failures/parking, not normal progress; it has no per-view unregister. `watchDoc(LiveDoc,c,context)` returns a document-only watch or undefined: `.value`, `.start(listener)`, `await .stop()`; context cancellation also stops it. Running callbacks remain caller-owned. Alternatively `documentState(LiveDoc,c,context)` returns a state: unsubscribe `.subscribe(...)`, then `.dispose()`. [Signatures/ownership](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/types.d.ts), [implementation](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/session/session.js).

**Inference:** register invalidation before initial reads; coalesce a dirty flag and refresh paginated `conversation.entries(...)` plus projected `snapshot(LiveDoc,...)` outside callbacks. Bound delivered counts/bytes, retained pages and progress projection. Scope unsubscribes/watch cleanup to the viewer; never close Harness on view disposal. This avoids `Conversation.watch` and bounds app delivery, not total Pi cache.

**3 — Evidence:** `handOver` replaces only `run.taskId`, preserving `run.inputs`; post-tools may append steered IDs. `endRun` settles all inputs and removes the run. **Inference:** capture immutable submission identity with host/store/conversation; observe LiveDoc, abort only its captured task when inputs contain that submission, await `waitForTask`, then reread across handover. If absent, stop following; never select a later unrelated run. Queued input instead uses `abortSubmission` as above. Handover may outrun Stop; cancellation is cooperative and cannot undo effects. Shared steers/batches mean abort affects every input in that run, so strict “touch no later input” requires preventing co-admission; this is not an unconditional guarantee. No internal task writes or conversation-wide abort fallback. [Published handover/abort behavior](https://unpkg.com/@earendil-works/pi-durable@1.4.0/dist/harness/generation.js).
