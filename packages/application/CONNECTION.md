# Independent connection boundary

The coordinator owns these types, shared handlers and browser/runtime adapters. Task 06 implements `SshLive(config)` in `packages/ssh` as a scoped `ConnectionService` layer. It imports no editor or Pi implementation and creates no root runtime. The process composition root owns one runtime; `makeConnectionClient(runtime)` enters the same handlers as native/transport calls.

V0 has one explicitly configured profile: public ID/label, SSH destination, remote loopback port and expected host/store identity. Its private configuration adds the host key and system SSH executable. Browser commands cannot supply a destination, port, credential or forwarded origin.

- `getConnection({})` returns the configured profile and current snapshot without starting SSH. States distinguish disconnected, connecting, connected, disconnecting and failed. Each admitted attempt has a fresh `connectionId`; connected state includes the authenticated health identity.
- `connect({ profileId })` admits only that configured profile and reuses its current attempt/connected generation rather than spawning duplicates. The module owns startup, health, cancellation and teardown within the process scope, with resource-appropriate concurrency; slow startup cannot globally block status or unrelated application commands.
- `disconnect({ connectionId })` releases only the captured generation. A stale caller cannot close a newer tunnel; return a typed conflict where necessary. Repeated release after that connection is gone is harmless. Ending connectivity never aborts remote agent work or stops its independent host.
- `watch()` observes status only. Ending an observer releases its resources without disconnecting the tunnel or disposing the process runtime. Watch resources use the established enclosing stream scope and `releaseResource` convention.

Only privileged consumers can call `ConnectionService.endpoint({ host })`. It returns `{ origin, token, expected, connectionId, health }` for the exact currently connected verified host/store, or fails visibly. It never connects/rebinds as a lookup side effect. This shape is absent from `ConnectionCommands` and browser exports. The reusable key is never transmitted: use the checked nonce-bound health protocol and separately authenticated future chat transport, with no bearer fallback.

The SSH module uses system OpenSSH, existing config/agent/key handling and host-key checking, a loopback-only forward and an owned child. It must not silently share an unmanaged multiplexed master that outlives teardown. There is no remote provisioning, job control, file synchronization or resend. Validate config/arguments, preserve host-key policy, keep keys out of arguments/logs and surface missing real-host access honestly. The actual implementation supplies process/port/exit/collision/cancellation/cleanup and authenticated-health tests; controlled processes do not qualify real SSH behavior.

The application adapter shares cancellation/error/observation logic across editor and connection clients. Four public fixture-service tests prove handler routing, one acquired connection graph across clients, status during an in-flight command, typed cancellation/pre-abort and observable finalizer failure. Existing editor/runtime and health regressions remain passing. This preparation supplies no SSH implementation or real connection, and introduces no editor startup dependency.
