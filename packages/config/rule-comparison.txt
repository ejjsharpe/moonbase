Moonbase native Oxlint baseline: missing rules and policy differences
===================================================================

Versions and scope
  Oxlint 1.90.0; eslint-config-universe legacy default/node/web at Expo e180d5676641699581298683ba7854c8b0d36771;
  eslint-plugin-unicorn recommended 79.0.0 (JavaScript/TypeScript recommended, not other-language presets).
  Baseline: oxlint --init correctness:error; default TypeScript/Unicorn/Oxc plugins and implicit ESLint core, plus native React.
  No individual lint-rule overrides, JavaScript plugins, import/node plugins, or type-aware mode.
  Selected native rules: 142; syntax/semantic rules active without type-aware mode: 127.
  Availability is compared by native rule names, with the explicit core TypeScript-extension aliases shown below.
  Matching names are not proof of identical implementation behavior. No claim of exact upstream parity is made.

Important changes
  react/rules-of-hooks is pedantic and is NOT enabled. react/exhaustive-deps IS enabled as an error (Universe disables it).
  no-control-regex IS enabled as an error (Universe disables it).
  Remaining shared lint checks use native defaults and error severity rather than Universe warning severities/options.
  Formatting remains in Oxfmt. ESLint rules disabled by Universe’s final Prettier config are not counted as missing active lint checks.
  No-floating-promises and other typed rules require separately enabling type-aware mode; TypeScript typechecking is a separate task.
