# Moonbase configuration

Shared native Oxlint, Oxfmt and TypeScript configuration for the Bun/Nx monorepo.

```sh
bun run lint
bun run lint:fix
bun run format
bun run format:check
bun run test
```

## Oxlint baseline

`oxlint.mjs` starts with the configuration generated by Oxlint 1.90.0's `oxlint --init`: the `correctness` category at error severity, built-in globals, and native TypeScript, Unicorn and Oxc plugins (ESLint core is implicit). The native React plugin is also enabled for this React/Electron monorepo. Thirteen approved safety and consistency rules are added as explicit overrides in `base.rules`. Filename casing is left unenforced so React component files can use PascalCase. There are no JavaScript plugins, and this package has no dependencies.

The `base`, `node` and `web` exports keep lint rules shared while root `oxlint.config.mts` selects Node versus browser globals for each package/path. Consumers inherit the root config when running `oxlint .` from their own directories. Typechecking remains a separate Nx target; type-aware linting is not enabled.

This baseline is not a copy of the upstream ESLint plugins' recommended presets. [The complete rule comparison](./rule-comparison.txt) lists checks missing from Universe default/node/web and Unicorn recommended, distinguishing native rules that are disabled, absent/renamed rules, parser coverage and differences in options/severity. It is pinned to the versions named in that file.

Both `react/rules-of-hooks` and `react/exhaustive-deps` are enabled as errors. The approved additions enforce strict equality (allowing `== null`), safe switch cases, valid React DOM properties, `const`/`let`, explicit type imports, `T[]`, `node:` imports and no nested ternaries. Explicit `any`, `@ts-ignore` and `@ts-nocheck` are banned; `@ts-expect-error` requires a description of at least ten characters. Duplicate parameters and legacy octal syntax are parser errors in strict/modules, but have no separate lint rules for sloppy CommonJS. Neither Buffer constructor form has a lint check in this baseline: `unicorn/no-new-buffer` exists natively but is not in the correctness category.

## Oxfmt

`oxfmt.json` keeps Universe's documented formatting options: width 100, two spaces, single quotes and same-line JSX brackets, with Prettier 3's trailing commas. Formatting runs separately from linting. Import and package JSON sorting are not added.

Source snapshots and their exact active UI copies remain unchanged. Oxfmt and lint auto-fixes exclude `packages/ui` because `check:foundation` compares those files byte-for-byte with the immutable source snapshot; remove those exclusions when the provenance check permits formatting changes. Existing documentation is excluded from this code-formatting adoption.

## TypeScript

The shared compiler settings live in `typescript/base.json`. Consumer packages declare `@moonbase/config` as a workspace dev dependency and extend its exported subpath:

```json
{
  "extends": "@moonbase/config/typescript/base.json",
  "compilerOptions": { "types": ["node"] },
  "include": ["src", "test"]
}
```

Each package keeps its own input files and environment-specific options. Root `tsconfig.base.json` forwards to this same base so other branches can keep their existing relative extends paths. Compiler behavior is unchanged.

Root `bun run lint` checks the repository once; the application Nx lint target also runs Oxlint. CI checks formatting and runs the config behavior test through Nx. Shared configuration changes invalidate relevant Nx caches. The behavior test runs the real tools locally to verify correctness rules/error severity, every approved addition, the allowed null-comparison/TypeScript-directive exceptions, snapshot exclusion and formatting.
