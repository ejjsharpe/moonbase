# Transcript reading

Desktop consumes the public [headless transcript owner](../../../packages/application/docs/TRANSCRIPTS.md). Only `state.transcript.entries` supplies history; latest `snapshot` supplies live/status evidence. Desktop does not merge snapshot entries into history, implement pagination, own hydrated caches or acquire another runtime. The composer, sidebar, editor, native chrome, recovery notices and shortcuts retain their owners. [Thinking, tool activity and recorded patches](ACTIVITY.md) and [stored images](IMAGES.md) share the generic ordered Part/source/Copy seams described here.

## Private presentation

`renderer/chat/transcript.tsx` owns DOM rows, semantic entry/part anchors, viewport-relative restoration, bottom following, automatic near-top/manual earlier loading, later navigation, Jump to latest and transient expansions. Disclosure keys fit application memory bounds even for maximal public identities; long keys use WebCrypto SHA-256. Programmatic anchor restoration cannot trigger another automatic earlier read; a user upward-scroll intent admits that same manual handler. The DOM retains at most 128 entry rows including live output. At that boundary the earlier action can reveal the extra historical row before navigating another window. Focused/selected Markdown blocks retain their current DOM and captured actions until focus/selection leaves. A per-view ResizeObserver restores the same anchor after hydration/folding/resize and disconnects on unmount. Explicit application around-entry/part anchors reveal generic disclosures; conversation Find adds its exact source/part/range intent through the same shared hook.

Live output belongs to the canonical newest window (`later === false`), independently of bottom following. At 128 rows, the oldest row remains while its saved anchor, actual focus or noncollapsed selection pins it; live output waits rather than evicting that row or exceeding the budget. An open stored-image viewer privately pins its exact source while portal focus is outside the row, retaining it through Base UI's focus return before ordinary row focus tracking takes over. Selection/focus events release this protection reactively, and explicit Jump to latest clears pins. A partly visible selected row may differ from the viewport anchor.

View memory restores the saved row/part and viewport-relative offset best effort, including after changed text. A missing part/row falls back nearby within the same exact backend/conversation; reader navigation releases the saved restoration. No view-only content proof, proof-readiness gate or proof error is exposed. Real history/manifest/content errors and recovery notices stay visible. Parts beyond the summary advance the supplied manifest handler; controller replacement consumes application-lifetime memory, while mounted DOM anchors handle subsequent size changes. A frame fence prevents restoration-generated scroll events from overwriting a supplied anchor. Retired live DOM stays pinned for active selection/focus, with current status/errors visible.

Pointer input and navigation keys from transcript controls also release pending restoration and capture the actual reading position. While a manifest is loading, visible snapshot-preview parts remain valid capture targets. Disclosure writes read the controller's current view at activation, preserving that newer anchor and other expansions; input-down toggle intent survives a capture that reveals the same part before activation. Explicit durable/live collapse remains authoritative for its mounted anchor. Conversation status and message come from the current snapshot even while old live DOM is pinned.

`markdown.tsx` uses directly exact-pinned `react-markdown@10.1.0`, `remark-gfm@4.0.1`, `remark-parse@11.0.0`, `unified@11.0.5`, `mdast-util-from-markdown@2.1.0` and `unist-util-visit@5.2.0` (with `@types/mdast@4.0.4`). ReactMarkdown consumes cached mdast blocks through unified's public parser hook. The same parser helper interprets privileged code selectors; there is no parallel fence scanner or original-body reconstruction. Parser fence events identify fenced code and closure; indented code/HTML do not contribute selectors. Assistant prose supports headings, lists, inert task markers, quotes, tables, inline/fenced code and links. User text stays literal. HTML/SVG/control/style source stays inert text; no transcript HTML is inserted, so transcript safety does not depend on an HTML sanitizer. External images become explicit links without requests; nested linked images keep separate target/source links. File/unsafe-scheme references remain readable. Only an explicit HTTP(S) action reaches native opening; failures stay visible.

Only a changed message is parsed. Shared definitions accompany its top-level AST blocks so later reference definitions reinterpret affected output correctly. Unchanged block signatures and stable positional React keys preserve sibling DOM; signatures include code-action source positions so shifted code cannot reuse a stale captured selector. The per-view LRU keys exact identity/revision/source/render inputs, retains at most 128 messages and 2 MiB including keys/source/AST/signatures, and clears on unmount. Mounted messages retain one parse result, including oversized results excluded from the LRU. Unknown/incomplete/oversized code stays readable without highlighting. Parser failure falls back to inert source. Parsing/highlighting/DOM retention never limit complete source Copy.

Code uses public Monaco language/token APIs, with public `colorize` only to await lazy language readiness; its returned HTML is discarded. No editor is mounted per block. Per-mounted-block memoization retains one exact code/language/readiness result, and skips highlighting for unknown/incomplete blocks or content over 64 KiB / 2,000 lines. Comments use shared supporting text; keywords use existing emphasis. Code folds after 40 lines and code/tool output and tables have independent overflow. Generic ordered parts preserve available content plus unsupported/redacted/unavailable, pairing, dropped-tail, error and interrupted evidence. Content/manifest reads remain progressive and have retry/restart actions; cache eviction is explained and rereadable.

## Native authority

The private `TranscriptNative` callbacks in `chat/wire.ts` capture an installed backend, use the existing preload command/cancellation channels and enter `ChatIpcSession` through authenticated main IPC. `main/chat-backends.ts` injects the actual async Electron clipboard and native browser capabilities. The existing exact main-frame/document guard, CSP, navigation/frame/permissions and provider-sign-in policy are unchanged. `chat/transcript-native.ts` is a privileged browser-graph input and creates no runtime.

Copy accepts an exact source and optionally a fixed part selection and private `code: {start}` selector. `start` is the shared parser's nonnegative safe-integer original UTF-16 node position, bounded by the selection's byte length. A message retrieves all ordered original authored user/assistant Markdown, preserving original CRLF/whitespace and excluding thinking/tool data. A part retrieves its exact original selection. Code Copy is parser-produced: native Copy independently parses the complete authorized original selection with the same pinned remark/GFM helper as the renderer, selects the fenced code node at that original position, then copies its `value` without further trimming or truncation. Markdown containers/fences are absent; parser line-ending/container normalization is allowed and meaningful code indentation remains. Renderer-provided text/body ranges and ordinal-only indexes are rejected. If partial hydration parsed a fence that the complete source reinterprets, the missing node identity produces a visible Conflict before any clipboard write. Indented literals and HTML never contribute code selectors; raw message/part Copy still includes them. Prefix-evicted content offers no relative code selector. `chat/transcript-source.ts` owns this private pure interpretation plus disclosure IDs. Input stays bounded by the existing chat request limit and at most two Copy jobs run per session. The selector stays constant-size; highlighting, DOM and hydration limits never clip Copy.

Main iterates all validated chunks independently of UI retention, checks schema/echoes/offsets/cursors and rejects binary text Copy. A live Copy installs its own captured-source watch and rejects stale/reconnecting/failed/disappeared/replaced incarnations. After iteration it requests fresh fixed-prefix evidence for every captured selection, fenced against newer observations. Up to three superseded proof rounds are permitted without restarting content iteration; continuing supersession is observable Conflict. Prefix replacement, tail rollover and unproved finalization fail before the single awaited clipboard write. Later appends stay outside the captured length. Cancellation/document replacement fence late results, retain actual IO/watch settlement and do not serialize Stop behind Copy. Once the OS write has begun it cannot be revoked; late cancellation is reported after its actual settlement rather than returned as success.

The native boundary materializes the complete selected text for one atomic clipboard write; its total string memory is proportional to Copy size. UI/cache/highlighting limits do not truncate it. Cleanup awaits every pending read and observation-close settlement, even if close rejects first. Failed close remains in the captured request/document/session cleanup outcome after the Copy reply; cancellation cannot acknowledge success and later disposal cannot erase it. A retained disconnected view reports cancellation rather than leaving a permanent Copying status.

Only explicit HTTP(S) URLs without credentials/control characters, at most 8,192 UTF-16 units, enter the document-scoped opener. It is distinct from provider authentication URL authority. Renderer-supplied source/path strings grant no filesystem or provider capability.

## Shared seams

- Activity: private consecutive activity groups share `Part` disclosure state, exact source/part anchors and fixed-part Copy. The direct maintained patch parser is consumed only by recorded unified-patch presentation; see [activity](ACTIVITY.md).
- Images: [stored-image validation, canvas thumbnails/viewer and scoped resource limits](IMAGES.md) consume fixed selections through the controller iterator and explicitly release hidden/offscreen content.
- Find: uses `jumpToEntry`/around reads, exact source/part/original UTF-16 intent in the shared disclosure hook, progressive source windows and the existing DOM source attributes. Only complete handlers advertise the Find capability.

## Conversation Find

The private Find bar composes the selected controller's transient `transcript.find` state. Cmd/Ctrl+F is handled only within Chat reading controls; inputs, textarea, contenteditable and the separate editor keep their own shortcut routing. Enter/Shift+Enter move through matches, Escape closes and restores prior reading focus. Search progress is explicit; no-match appears only after completion. Upgrade/failure and explicit Refresh are visible.

The shortcut and transcript Find button share private `activateChatFind` in `renderer/chat/find.tsx`. Each explicit activation opens the selected bar and focuses its existing labelled field with `preventScroll`, preserving the query, active match, fixed cutoff and reading position. The action resolves only the initiating connected Chat view, bound to its exact backend/selected target, and checks the current selection/open state after publication. Background publications and async reveal do not acquire focus; composer/editor shortcut ownership stays separate.

The exact `{source, partId, start, end}` active range, in original UTF-16 units, remains separate from viewport pixel anchors. Entry/part data attributes are the shared disclosure/reveal seam for tools/images. Existing authorized around-entry navigation pages unloaded rows; generic manifest hydration reaches the exact part and opens the owning thinking/tool disclosure. The renderer progressively loads through the match, using chunk UTF-16 bases even after the 8 MiB cache evicts its prefix. It compares the hydrated original match with the returned original snippet, then shows at most the match plus 120 surrounding UTF-16 units on either side, preserving code-point boundaries. Rich Markdown stays in its surrounding reading UI; no custom Markdown parser or source-map engine is introduced. Matched hydration preserves the existing reading body; a newly revealed part starts with its compact preview. Full content/Copy remain independently available.

Find adds its intent to the one private `useDisclosure` used by Part and containing Activity. Unrelated active matches suppress old implicit semantic anchors. Same intent respects explicit collapse; a different range in the same part reveals again. If completed manifest descriptors were evicted, Find replays the released manifest once per active intent, preserving its cutoff and exposing an unavailable-part error if replay still cannot find the part. Stale replay completion cannot alter a newer intent. Frozen reading text cannot label a partial recorded patch as complete. The generic Part Find effect resumes the controller's `partial` content state, including zero loaded bytes and no continuation cursor after a cancelled initial read.

Reveal scrolls only the transcript and keeps the Find field/selection focus. Wheel, reading keys, pointer reading and explicit history/latest navigation release pending restoration and cancel Find reveal/hydration while retaining query/result identity; hydration cannot restart until a new revealing intent. Query replacement/Hide/close/disposal cancel the query as well; a late response cannot retarget the selected conversation. Explicit disclosure collapse remains respected.

## Testing

`test/transcript.spec.ts` covers reading, navigation, restoration, disclosure, Copy and Find in controlled browser fixtures, including unloaded folded parts, literal Unicode/metacharacters, Find shortcuts and reactivation, and a 9.6 MB non-ASCII source beyond prefix eviction followed by navigation back. Controlled fixtures use temporary stores, faux providers and authenticated loopback forwarding; they use no real provider quota or SSH host. Generated output belongs in desktop's ignored `test-results/`.

Tests must not read or write the real OS clipboard; inject clipboard and open callbacks, including awaited failures. Timing observations from fixtures are not device performance guarantees. Packaged execution, VoiceOver/manual accessibility and real OS clipboard behavior are outside the automated suites.
