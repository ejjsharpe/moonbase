# Desktop model and document ownership

Main acquires workspace, local Pi and optional remote-chat/SSH capabilities once in separate scopes of one runtime. IPC envelopes and observations capture their immutable backend ID; the selected renderer target cannot reroute late responses. Each trusted document owns an Effect child scope under that runtime; each bounded IPC request/watch owns a child scope. The existing cancellation channels use invoke/handle and return a validated `Reply<null>` only after local wait/watch finalizers settle. Cancellation never acknowledges mutation rollback or remote task termination. Repeated close joins the retained outcome; document replacement immediately fences delivery/authority before draining old scopes. Successful native captures install their privileged release finalizer in the captured document scope before references are published. Late capture, picker and command completion cannot grant authority to the replacement document. Claimed native descriptors remain workspace-owned.

Each live renderer acquires one public `createMoonbaseApplication` using validated bridge clients and stable storage/instance identities. The application creates its client runtime and aggregate scope, acquires and binds each editor/chat once, and owns removable acquisition scopes and cleanup. It installs no backend capability. The renderer mounts its own `DesktopShell` with that application and approved native callbacks; it creates no feature model or runtime. Desktop owns main navigation, project/Chat tabs, Chat presentation, focus routing and project layout. It supplies the exact checkout and editor controller to `Workbench` from `@moonbase/workbench`, which renders the file sidebar, buffers, Monaco and exact editor prompts. Desktop retains wire validation, private storage, native subscriptions and acknowledgments. See [application lifecycle](../../../packages/application/docs/LIFECYCLE.md). Edits, chat preservation and editor recovery readiness remain synchronous unload gates. The main process independently releases document resources after committed navigation or process loss; renderer unload cleanup is best effort.

View switching keeps the editor mounted and detaches/resumes chat observation. **Close Chat panel** first preserves its saved work, synchronously fences model admissions, removes its UI, and retains an Effect cleanup task in the application's aggregate scope. The editor remains usable. **Open Chat panel** acquires a fresh model only after successful cleanup releases that namespace. Failed cleanup retains the namespace lease, appears in a bounded application-owned error area and remains part of Quit's cleanup result. No lifecycle action Stops remote work or automatically repeats Send.

Desktop calls its internal `DesktopShellHandle.prepareQuit()` to reveal editor prompts and uncertainty controls even from Chat. It delegates to application, which preserves chat, runs the editor's exact Save/Discard/Cancel gate, then preserves newer chat edits. A veto retains the live UI. Before consent returns, application synchronously fences every model and retained workflow admission, then preserves the latest chat state. The renderer becomes inert, unmounts view resources and awaits application disposal, which drains every closing task and releases its scope/runtime. It returns the matching existing disposal acknowledgment with an optional strictly validated bounded error DTO. Main attempts all its releases and reports failures natively before exit. A failed cleanup does not restore a disposed UI. Forced document/process loss is not a physical durability guarantee.

Public data/schema and privileged Effect service contracts live in independent `packages/contracts`; desktop adds only private IPC/native/disposal envelopes, raw size/depth bounds and document authority. Recovery replies use the strict saved-data decoder, so unfamiliar nested fields cannot be projected away and republished. The private configuration reader retains owner/no-follow/16 KiB/strict-field/actor/32-character-minimum rules while consuming the SSH decoder's privileged profile and executable policy.

Source tests hold/fail actual IO observation finalizers. Native fault tests hold cancellation delivery and inject a safe cancellation acknowledgment failure through the test-only entry, then verify the real renderer's removal, namespace gate, visible error and Quit drain. They do not claim an injected acknowledgment is a real OS release failure. The shipped package excludes all such hooks; packaged tests exercise its normal close/reopen and lifecycle paths. Real SSH/providers, OS gestures, VoiceOver, physical durability, Intel and distribution remain separate qualification.

Optional chat configuration/context/model acquisition failures are application-owned status, distinct from unavailable and cleanup-blocked. The editor remains usable, while uncertain startup evidence vetoes reload/Quit until an explicit successful reopen. Invalid private configuration still fails in privileged main before a window opens. Required factory failure unwinds acquired resources before rejection; desktop renders its safe bounded error and preserved-recovery guidance, registers the existing ready/Quit actions and reports failure through the disposal acknowledgment to the native error dialog.

Committed main-document replacement clears the old pending Quit identity while retaining Quit intent. After replacement readiness, main requests fresh preservation and disposal acknowledgments. Obsolete document IDs cannot authorize the replacement; document loss does not establish successful cleanup. The existing renderer-crash Recover/Quit policy remains separate.

## Local targets and final Quit

Desktop injects named Local/remote targets into the one renderer application. Each acquisition binds browser clients to its immutable backend ID and exact host/store/actor and supplies its own storage key. Closing/switching disposes client observations/controllers, not the root-owned backend. A replacement document gets new IPC/provider ownership while Pi execution stays in main. Provider setup is cancelled when its owning controller/document is released; old flow/prompt answers and URLs cannot authorize a successor.

The renderer’s final `confirmQuit` hook runs only after application admissions are fenced. Main fences local Pi mutations and scans all Pi tasks, unfinished intent metadata and in-flight admissions before showing Keep running/Quit. Keep running and document replacement restore main admissions; Quit retains the fence through normal runtime cleanup. Native folder approval is injected into the local service so shared Create dispatch resolves a matching committed receipt before requiring approval for new work. No Stop is issued during teardown, and remote work is unaffected. Local backend failure is retried only on explicit context/panel acquisition and unwinds its failed scope; no backend is acquired twice while live.

The same main-owned confirmation guards recovery/startup-failure Quit paths that have no live application hook. Confirmation is tied to the current document and Quit intent; obsolete scan/dialog/acknowledgment completions cannot clear a replacement’s intent or reopen its admissions. Activity-scan failure in crash recovery is reported safely and reloads the renderer instead of escaping the event handler.
