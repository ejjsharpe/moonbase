# Recorded thinking, tools and patches

Desktop private presentation consumes public structured parts and the headless transcript owner. It owns no execution, transcript store, polling loop or filesystem capability.

## Reading activity

`activity.ts` groups only consecutive recorded activity parts within each entry. User and assistant text retain their exact position before, between and after those runs, including across manifest/history pages. Later result entries keep their recorded position; the renderer never moves them into an earlier call. Each group and each thinking/input/output/detail part defaults folded. Compact summaries retain work state, thinking availability/byte progress, output byte progress/previews, failures, interruption, missing results and unmatched/ambiguous pairing. Live responses distinguish pending, unavailable/redacted and no supplied thinking. No provider signatures or private diagnostics are requested.

Read/write/edit inputs show their recorded path; bash shows its recorded command. These are inert summaries. Requested and executed arguments retain distinct labelled parts, generic JSON and exact original Copy. A request alone does not prove execution. Writes show captured arguments/content without an invented before/after diff. Unknown tools retain all supplied arguments, output and public details.

An originating call receives status evidence only from parts marked matched with the exact `call.entryId` and `call.partId`, within the same full target. Neither names nor reused call IDs join records. Missing evidence in the current bounded window says result not shown; it cannot imply a successful result or authoritative missing-result state. Explicit runtime missing-result/ambiguous/unmatched/interrupted states remain visible. Dropped-byte/line evidence remains attached to the retained output. Durable and live evidence paths use a matching manifest only when it contains parts, mirroring Entry's preview fallback, so a held or failed first manifest read retains the originating call's known state alongside the visible result preview and retry error.

`transcript-parts.ts` shares descriptor selection between the live body, activity evidence and reading capture. Successful loaded pages retain authority until the controller marks them stale. For an exact-source live manifest marked `source-changed`, the current snapshot's ordered prefix replaces old prefix descriptors, including bytes/revision/state, followed by loaded parts outside that prefix in their recorded order. The public summary contains the first four parts; opaque IDs supply identity, never sorting. Foreign/retired sources cannot contribute loaded parts. Manifest warnings remain visible, and paged-only descriptions remain readable until explicitly reloaded. Hydration and Copy still match the full source plus exact part/byte/revision selection; no content proof is inferred from reconciliation.

Current live content is present whenever the canonical window reaches the newest boundary (`later === false`), independently of bottom-follow mode. Reading a durable row in that window must not make a running tool disappear. Earlier windows with a later continuation omit live output. The existing 128-row budget, exact live-source selection pinning, current recovery notices and explicit Jump to latest remain in charge.

## Disclosures and other consumers

`transcript.tsx` shares the private `useDisclosure` hook between generic Parts and their activity wrapper. Application owns transient expansion memory. An exact supplied child-part anchor reveals both wrappers. Its semantic identity excludes viewport pixel offset; an explicit collapse remains collapsed across unrelated/live updates while that same intent remains present. A different part anchor can reveal again. Children stay mounted under a hidden group so their own disclosure state survives a group fold. Viewport restoration uses the visible group when its saved child is folded.

The hook carries pointer/key-down toggle intent, pointer cancellation and current-controller-view click writes into both Part and Activity. A capture that implicitly reveals a part between input and click does not reverse the reader's original toggle intent. Collapse records the current captured child anchor, including a child in an Activity run, without spreading cached view state back into the controller.

Every entry/part retains `data-transcript-entry` / `data-transcript-part`, exact sources, generic hydration and fixed-source native Copy. There is no specialist Find API. Find's exact full source/part/original UTF-16 range supplies reveal intent only to the matching Part and containing group; unchanged intent respects collapse and a new range reveals again. Active matches elsewhere suppress old implicit anchors. Original match coordinates remain separate from the viewport anchor's pixel offset. Stored image parts retain the same generic nodes, hydration and ResizeObserver/eviction lifecycle.

`part-body.ts` owns one local presentation snapshot for each plain activity Part: the text, full source, exact descriptor and retained byte window stay together while a real noncollapsed selection intersects that body. Focus alone does not hold it. Current compact summaries/status, hydration and actual read errors/retry controls continue updating. A small notice distinguishes previously read output from current progress. Clearing selection shows the current hydrated body; a loaded body can bridge pending/failed replacement hydration only while application still retains its old content window. Eviction after release yields to the current bounded preview rather than creating another content cache. There is no version history or extra read loop.

The snapshot identity includes backend/full source/part; replacement identities replace local snapshots, and Part disposal removes the selection listener. Existing source-retirement selection presentation and intentional Jump to latest keep their owners. Copy pointer/key input captures the displayed descriptor before activation can release selection. A changed presentation identity before activation reports a retry without dispatching the old intent to a new source/backend. Native validation still independently accepts a retained fixed prefix or rejects a replacement/retired source without writing; old text is never labelled with new byte/revision evidence. Generic Markdown, recorded patch and stored-image presentation keep their existing owners.

Find keeps its saved reading text, bounded original-source window and partial-patch completeness guard ahead of this plain-body path. A matching Find part disables plain-body retention; its source-window presentation and fixed-source Copy remain owned by Find. The reading-text calculation is memoized so React Compiler can preserve the combined presentation snapshot.

## Historical patches

`recorded-patch.ts` calls the public `parsePatch` API from exact direct `diff@8.0.4`; its installed README and public declarations define the consumed hunk shape. The viewer renders read-only files/hunks, actual old/new coordinates, context/addition/removal lines and recorded EOF notices. Shared StyleX tokens distinguish line kinds alongside their literal prefixes. There is no line pairing, synthetic context, syntax guessing, current-file read or patch application.

A missing terminal newline is normalized only in the argument supplied to `parsePatch`, preventing its silent missing-count adjustment at bare EOF. Authored source remains unchanged in fallback display and complete fixed-source Copy.

Unified patches are the structured view; stored numbered diff parts remain an explicit source fallback with their original numbers. Incomplete, malformed, unsupported or over-budget unified patches receive labelled readable source. Parsing is limited to 64 Ki UTF-16 units / 2,000 source lines; fallback display pages hold at most 16,002 UTF-16 units within the currently hydrated source, overlapping a boundary code point when needed to keep emoji intact. Previous/Next source and generic Read more/Read from start allow continued reading. This is a display budget, not permanent source clipping.

Copy patch/diff uses the existing document/backend-scoped native fixed selection. Main independently iterates and validates the complete retained source, including parts too large to parse/display. Native cancellation, source freshness, exact target/document checks, awaited clipboard failures and Stop independence are unchanged. Recorded path strings never grant authority to open files or reconstruct history.

## Testing

Controlled fixtures use temporary stores, faux providers/tools and injected clipboard callbacks. The native local harness installs an inert clipboard writer before loading main, so no test can write the OS clipboard accidentally. Keyboard-activation fixtures wait two animation frames after focus so focus-induced scrolling settles before they toggle.
